# `batch/` -- HTCondor submission layout

All condor submission files, their wrapper shell scripts, and the small
C++ list-generator macros are grouped by pipeline stage. Each stage directory
is self-contained: `cd` into it before running `condor_submit` (relative
`executable =` / `output|error|log =` / `queue ... from <file>` lines in every
`.sub` resolve against the directory you submit from).

```
batch/
├── README.md                              -- this file
├── dch_tight/                             -- stage 1: event selection + histogramming (DCH_tight.C)
│   ├── dch_tight.sub                      -- whole-year job (one per year, nProc=8 worker threads)
│   ├── dch_tight_perfile.sub              -- one job per input file ($(year),$(idx) from filelist.txt)
│   ├── dch_tight_chunk.sub                -- one job per (year,file,chunk) from chunklist.txt
│   ├── dch_tight_chunk_retry.sub          -- reruns only the (year,idx,chunkidx) in retry_chunklist.txt
│   ├── dch_tight_merge_chunks.sub         -- merges chunked output back into per-sample .root (see MergeChunkHists.C)
│   ├── dch_tight_merge_chunks_remaining.sub -- same, for a specific older/partial production (kept for reference)
│   ├── run_dch.sh                         -- wrapper for dch_tight.sub (cmsenv + root -l -b -q 'DCH_tight.C+(...)')
│   ├── run_dch_perfile.sh                 -- wrapper for dch_tight_perfile.sub
│   ├── run_dch_chunk.sh                   -- wrapper for dch_tight_chunk(_retry).sub
│   ├── run_dch_merge_chunks.sh            -- wrapper for dch_tight_merge_chunks(_remaining).sub
│   ├── gen_filelist.C                     -- (re)generates filelist.txt from filemap/FileMap.h
│   ├── gen_chunklist.C                    -- (re)generates chunklist.txt (needs a grid proxy; reads each file's entry count over xrootd)
│   ├── MakeFileList.C                     -- older/simpler filelist.txt generator, kept for reference (see note below)
│   ├── resubmit_failed.sh                 -- scans logs/, rewrites retry_chunklist.txt, optionally resubmits (see below)
│   └── logs/                              -- condor .out/.err/.log land here at runtime (gitignored, not shipped)
├── stackhist/                             -- stage 2: stacked-plot production (Stackhist.C / Stackhist_multiplicity.C)
│   ├── stackhist.sub                      -- 40 jobs: 8 var-chunks of 4 x 5 periods, reads filelist_stackhist.txt
│   ├── stackhist_multiplicity.sub         -- same, for Stackhist_multiplicity.C
│   ├── stackhist_run2_retry.sub           -- reruns only the (year,first) in run2_only.txt, NVARS=4
│   ├── stackhist_multiplicity_run2_retry.sub -- same, for Stackhist_multiplicity.C
│   ├── run_stackhist.sh                   -- wrapper for all four stackhist*.sub files
│   ├── filelist_stackhist.txt             -- (year,first-variable-index) pairs; hand-edit if you change the variable count (see root README)
│   └── resubmit_failed_stackhist.sh       -- scans logs/, rewrites run2_only.txt, optionally resubmits (see below)
└── yieldplots/                            -- stage 3: yield tables (YieldPlots.C)
    ├── yieldplots.sub                     -- 5 jobs: one per year + Run2
    └── run_yieldplots.sh                  -- wrapper
```

(`logs/` subdirectories exist in the repo as empty placeholders -- condor
writes `.out`/`.err`/`.log` files into them at submit time; they are
`.gitignore`d so a production's logs never get committed.)

## What was dropped from the AFS working copy, and why

- `dch_tauFR*.sub`, any `*tauFR*` wrapper -- fake-rate pipeline, out of scope
  for this migration (see the root README).
- `batch/logs/` (the actual run logs that were present on AFS) -- these are
  run-output, not framework code; only empty `logs/` placeholders are kept.
- `filelist.txt`, `chunklist.txt` -- these are **regenerated** output of
  `gen_filelist.C` / `gen_chunklist.C` (confirmed by reading both scripts'
  header comments and bodies: each opens an `ofstream` to exactly that file
  from `filemap/FileMap.h`'s current sample list). Shipping a stale snapshot
  checked in would silently diverge from `filemap/FileMap.h` the moment a
  sample is added/removed, so they are regenerated on demand instead:
  ```
  root -l -b -q batch/dch_tight/gen_filelist.C     # from the repo root
  root -l -b -q batch/dch_tight/gen_chunklist.C    # needs a valid grid proxy
  ```
- `retry_chunklist.txt`, `run2_only.txt` -- these were **not** regenerated by
  any script; they were a hand-curated list of the specific jobs that failed
  in one past production campaign (confirmed: no generator references them).
  Shipping them would silently "resubmit" jobs from a dead campaign. They are
  replaced by the `resubmit_failed*.sh` scripts below, which rebuild the same
  two files from the *current* set of condor logs each time you need to
  retry something.

## Resubmitting failed/incomplete jobs

Two scripts generalize the existing `*_retry.sub` / `retry_chunklist.txt` /
`run2_only.txt` convention (which already existed in the AFS working copy as
a hand-maintained, one-off list) into something you rerun after every batch:

### `dch_tight/resubmit_failed.sh`

```
cd batch/dch_tight
./resubmit_failed.sh            # scans logs/, (re)writes retry_chunklist.txt
./resubmit_failed.sh --submit   # also condor_submit dch_tight_chunk_retry.sub
```

It reads `chunklist.txt` (the full expected `(year,idx,chunkidx)` set --
regenerate it first with `gen_chunklist.C` if you don't have it), and for
each entry checks `logs/dch_tight_chunk_<year>_<idx>_<chunkidx>.log` for a
`return value 0` termination line and its matching `.err` for an
error/segfault/abort string. Anything missing or failing either check is
written to `retry_chunklist.txt`, which `dch_tight_chunk_retry.sub` already
queues from.

### `stackhist/resubmit_failed_stackhist.sh`

```
cd batch/stackhist
./resubmit_failed_stackhist.sh stackhist                  # or stackhist_multiplicity
./resubmit_failed_stackhist.sh stackhist --submit
```

Same idea, over `filelist_stackhist.txt`'s `(year,first)` pairs and the
`stackhist_*_$(year)_$(first).log` condor logs; writes `run2_only.txt`, which
`stackhist_run2_retry.sub` / `stackhist_multiplicity_run2_retry.sub` already
queue from (these rerun each listed chunk with `NVARS=4` rather than the
original variable-chunk size, exactly as the pre-existing retry `.sub` files
already did).

Both scripts only use information already on disk (condor's own per-job logs)
-- no new job-numbering convention was invented; they just automate filling
in the two list files the existing `_retry.sub` files were already wired to
read.

## One-time edits before submitting anything

Every `.sub` file in this tree has:
```
x509userproxy  = /afs/cern.ch/user/a/atahmad/.grid_proxy/x509up.pem
```
Update this to your own grid proxy path (condor needs an absolute path here).

Every `run_*.sh` wrapper has, near the top:
```bash
CMSSW_SRC_DIR="/afs/cern.ch/user/a/atahmad/updated_analysis/CMSSW_13_0_10/src"
cd "$CMSSW_SRC_DIR"
```
Update `CMSSW_SRC_DIR` to wherever you built this CMSSW release (condor jobs
need an absolute path here too -- see the root README's Prerequisites /
Step 0 for the full one-time setup).
